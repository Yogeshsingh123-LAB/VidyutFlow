## 3. Phase 11A Persistent Data Architecture & Consolidation Design

### 3.1 Single Authoritative Backend Boundary
To eliminate the Phase 11 in-memory data island while preserving 100% backward compatibility with `/api/meter-readings/*` and existing tests:
1. **FastAPI + SQLAlchemy Schema (`backend/app/models.py` + Alembic migration `006_phase11a_persistent_meter_reading_system.py`)**:
   - `meter_configurations`: Active configuration per `connection_no` (`serial_number`, `digit_count`, `integral_digits`, `fractional_digits`, `multiplier`, `allow_rollover`, `max_rollover_value`, `current_version`).
   - `meter_configuration_versions`: Append-only version log (`id`, `connection_no`, `version`, `serial_number`, `digit_count`, `integral_digits`, `fractional_digits`, `multiplier`, `allow_rollover`, `max_rollover_value`, `changed_by_id`, `changed_by_name`, `reason`, `created_at`).
   - `meter_events`: Append-only meter rollover/replacement events (`id`, `reading_id`, `connection_no`, `event_type`, `old_meter_final_reading`, `new_meter_start_reading`, `rollover_max_value`, `effective_consumption`, `recorded_by_id`, `recorded_by_name`, `notes`, `created_at`).
   - `meter_reading_submissions`: Canonical reading records (`id`, `client_uuid`, `connection_no`, `consumer_no`, `consumer_name`, `subdivision`, `submitted_by_id`, `submitted_by_name`, `submitted_by_role`, `submitted_at`, `capture_mode`, `work_order_id`, `previous_reading`, `previous_reading_date`, `submitted_reading`, `reading_date`, `cycle_days`, `multiplier`, `effective_consumption`, `status`, `provisional_amount`, `provisional_breakdown_json`, `meter_Config_version`, `threshold_version`, `photo_id`, `reviewed_by_id`, `reviewed_by_name`, `reviewed_at`, `review_note`, `corrected_reading`, `demo`).
   - `meter_ocr_results`: Normalized OCR extraction records (`id`, `reading_id`, `meter_id`, `engine_version`, `raw_text`, `candidate_reading`, `normalized_reading`, `confidence`, `requires_review`, `manual_override`, `override_reason`, `quality_Passed`, `quality_warnings_json`, `extracted_at`).
   - `meter_ambiguous_digits`: Individual ambiguous digit flags (`id`, `ocr_result_id`, `reading_id`, `position`, `char_value`, `alternatives_json`, `confidence`, `reason`).
   - `meter_private_photos`: Private encrypted photograph metadata (`id`, `owner_type`, `owner_id`, `connection_no`, `consumer_no`, `uploaded_by_id`, `uploaded_by_role`, `storage_key`, `mime_type`, `byte_length`, `sha256`, `encryption_key_id`, `metadata_stripped`, `created_at`). Raw image bytes are encrypted at rest via `encrypt_upload_at_rest` (`AES-256-GCM` + `HKDF-SHA256`) and stored through `get_storage_provider()`, never exposed via public URLs.
   - `meter_reading_review_history`: Append-only reading review audit trail (`id`, `reading_id`, `action`, `previous_status`, `new_status`, `actor_id`, `actor_name`, `actor_role`, `note`, `corrected_reading`, `created_at`).
   - `meter_anomaly_cases`: Anomaly case records (`id`, `reading_id`, `connection_no`, `consumer_no`, `consumer_name`, `subdivision`, `category`, `severity`, `status`, `summary`, `reasons_json`, `evidence_json`, `expected_value`, `recorded_value`, `review_action`, `threshold_version`, `recommended_action`, `assigned_role`, `resolution_note`, `adjusted_units`, `adjusted_amount`, `resolved_by_id`, `resolved_by_name`, `created_at`, `updated_at`, `demo`).
   - `meter_anomaly_status_history`: Append-only anomaly status history (`id`, `anomaly_id`, `from_status`, `to_status`, `actor_id`, `actor_name`, `actor_role`, `note`, `adjusted_units`, `adjusted_amount`, `created_at`).
   - `consumer_billing_reviews`: Consumer billing review requests (`id`, `client_uuid`, `bill_no`, `connection_no`, `consumer_no`, `consumer_name`, `subdivision`, `category`, `description`, `preferred_reading`, `evidence_photo_id`, `status`, `linked_reading_id`, `linked_anomaly_case_id`, `validation_snapshot_json`, `resolution_note`, `resolved_by_id`, `resolved_by_name`, `created_at`, `updated_at`, `demo`).
   - `consumer_billing_review_history`: Append-only billing review status/note history (`id`, `review_id`, `status`, `actor_id`, `actor_name`, `actor_role`, `note`, `created_at`).
   - `meter_threshold_policy_versions`: Append-only threshold policy versions (`id`, `version`, `minimum_history`, `high_daily_ratio`, `low_daily_ratio`, `high_daily_units`, `reason`, `changed_by_id`, `changed_by_name`, `created_at`).
   - `financial_adjustment_proposals`: Financial adjustment proposals (`id`, `anomaly_case_id`, `billing_review_id`, `bill_no`, `connection_no`, `consumer_no`, `consumer_name`, `subdivision`, `original_units`, `original_billed_amount`, `proposed_adjusted_units`, `proposed_adjustment_amount`, `proposed_revised_amount`, `adjustment_type`, `reason`, `calculation_basis`, `status`, `ledger_application_status`, `ledger_reference_id`, `ledger_applied_at`, `proposed_by_id`, `proposed_by_name`, `proposed_by_role`, `proposed_at`, `approved_by_id`, `approved_by_name`, `approved_by_role`, `approved_at`, `approval_note`, `demo`).
   - `financial_adjustment_history`: Append-only financial adjustment lifecycle log (`id`, `adjustment_id`, `from_status`, `to_status`, `ledger_application_status`, `actor_id`, `actor_name`, `actor_role`, `note`, `created_at`).
   - `meter_notification_dedup`: Persistent notification deduplication ledger (`id`, `dedupe_key`, `recipient_key`, `category`, `reference_id`, `notification_id`, `created_at`).
   - `actor_idempotency_records`: Actor-scoped idempotency ledger (`id`, `client_uuid`, `actor_id`, `endpoint`, `payload_hash`, `resource_type`, `resource_id`, `response_status`, `response_body_json`, `created_at`). Unique index on `(client_uuid, endpoint)` with verification that `actor_id` and `payload_hash` match on retry; mismatches raise HTTP `409 Conflict`.
2. **Compatibility Proxy & Unified Contract**:
   - FastAPI exposes `/v1/meter-readings/*` (and `/api/meter-readings/*` plus alias paths via `ApiVersionPrefixMiddleware`).
   - Node's `/api/meter-readings/*` route handler proxies to the FastAPI backend when running in full-stack mode and enforces the exact same actor+endpoint+payload-hash idempotency, encrypted photo vault semantics, and append-only audit histories.
